## Local verification

- Pest: 126 passed / 844 assertions and 1 PostgreSQL-only integration test skipped by its environment guard on the host. The single-business middleware tests cover context resolution, fail-closed missing/ambiguous business configuration, suspended membership, and runtime keys in `.env.example`. Messaging settings tests cover configured defaults, owner update, normalization, audit, validation, and denied staff access. Service catalog/category tests cover permission grants, business scoping, create/edit/delete, service assignment, inactive state, audit logging and additive migration reversibility. Database-queue health is tested before and after a real queue-worker iteration. The PostgreSQL concurrency integration test passed separately on PostgreSQL 17 with 15 assertions. The backup unit test passed 1 test / 3 assertions, including tamper rejection; an isolated PostgreSQL 17 backup/restore drill restored and queried a known test row. Playwright: 7 Chromium tests passed, including owner MFA and mobile settings update/reload, the mobile service/category create/edit/status workflow, private sign-in/recovery visibility, customer create/archive/restore, consent, notes, tags, visit lifecycle, inbox controls, and permission-gated page coverage. Deployment/rollback shell control flow passes its fake-Docker test.
- PHPStan/Larastan, Pint, TypeScript, ESLint, Prettier and Vite production build passed. Inertia pages are lazy-loaded; the largest built chunk is 356.81 kB.
- Composer validation and locked dependency audit passed; Docker Compose configuration parsed successfully.
- The application has 74 registered non-vendor routes and no active booking, appointment, availability, payment or subscription endpoints.

## Not verified here

The host runtime lacks `pdo_pgsql`; `php artisan migrate:status` fails with “could not find driver.” Disposable PostgreSQL tests cover fresh migrations, concurrent message claiming, stale-message recovery and an encrypted backup/restore into a new database. The configured database migration state, existing business data and existing-dataset constraints were not inspected. The original folder-grouped commits and subsequent catalog commits have been pushed to `main` with no co-author trailers. Broader authenticated CRM write workflows and full accessibility review are still needed. Live Meta/WhatsApp and email behavior, external privacy/legal compliance, production deployment, remote backup copy/retention and production restoration remain unverified.
